## 0. 完整环境配置

> **本节提供从零开始的完整环境搭建步骤**，涵盖硬件要求、软件安装、数据库初始化、Docker 部署、项目构建和防火墙配置。如果是首次部署，请按顺序完整阅读。

### 0.1 硬件要求

| 指标 | 最低配置 | 推荐配置 |
|------|----------|----------|
| **CPU** | 4 核 | 8 核（分布式模式下各模块独立进程，多核可显著提升并行算路性能） |
| **内存** | 8 GB | 16 GB（Unity WebGL 在浏览器中渲染约占用 2 GB 内存；多车并发 + 大地图需更多 RAM） |
| **磁盘** | 2 GB 可用空间 | 5 GB（含项目源码 ~50 MB、Maven 本地仓库 ~500 MB、Docker 镜像 ~200 MB、运行日志） |
| **网络** | 局域网 / 同一 WiFi | 所有参与分布式联调的机器必须在同一局域网， |

> **注意**：如果仅在单机运行全部模块（单机模式），最低配置即可满足。四人分布式联调时，Person A（基础设施主机）建议 16 GB 内存。

### 0.3 数据库初始化

SQL Server 需要**预先创建数据库 `substation-patrol`（可手动创建或由 SA 账号在首次连接时自动创建）。项目启动时 **Display 模块** 的 `DatabaseManager.initDatabase()` 会自动建表，所有建表语句使用 `IF NOT EXISTS`，**幂等安全，可重复执行**。

#### 0.3.1 数据库连接参数

> 数据库连接参数可通过 `deploy/infra.local.json` 配置（Person D 专用）。未配置时使用以下默认值（定义于 `DeployConfig.java`）。

| 参数 | 默认值 | 配置来源 |
|------|--------|----------|
| **JDBC URL** | `jdbc:sqlserver://localhost:1433;databaseName=substation-patrol;encrypt=false;trustServerCertificate=true` | `infra.local.json` → `dbHost` / `dbPort` / `dbName` |
| **用户名** | `sa` | `infra.local.json` → `dbUser` |
| **密码** | `Root@1234` | `infra.local.json` → `dbPassword` |
| **默认管理员** | `admin` / `admin123` | `DatabaseManager.insertPresetAdmin()` 硬编码 |

`infra.local.json` 中的数据库字段（可选，仅 Person D 需要配置）：

```json
{
  "dbHost": "localhost",
  "dbPort": 1433,
  "dbName": "substation-patrol",
  "dbUser": "sa",
  "dbPassword": "Root@1234"
}
```

> **安全提醒**：首次部署后请立即修改 `sa` 密码和 `admin` 账号密码。密码可通过修改 `infra.local.json` 中的 `dbPassword` 字段更新（改后重启 Display 生效），无需改动代码。生产环境建议使用 Windows 集成身份验证替代 SA 账号。

#### 0.3.2 自动创建的表结构

**表 1 — `users`（用户表）**

```sql
CREATE TABLE users (
    id INT IDENTITY(1,1) PRIMARY KEY,
    username NVARCHAR(50) NOT NULL UNIQUE,       -- 登录用户名
    password NVARCHAR(200) NOT NULL,              -- BCrypt 哈希密文
    role NVARCHAR(20) NOT NULL DEFAULT 'simulator', -- admin / simulator / analyst
    display_name NVARCHAR(50) NULL,               -- 显示名称
    status NVARCHAR(20) NOT NULL DEFAULT 'active', -- active / disabled
    created_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME()
);
```

**表 2 — `registration_requests`（注册请求审核表）**

```sql
CREATE TABLE registration_requests (
    id INT IDENTITY(1,1) PRIMARY KEY,
    username NVARCHAR(50) NOT NULL,               -- 申请用户名
    password NVARCHAR(200) NOT NULL,              -- BCrypt 哈希密文
    role NVARCHAR(20) NOT NULL,                   -- 申请角色
    display_name NVARCHAR(50) NULL,               -- 显示名称
    status NVARCHAR(20) NOT NULL DEFAULT 'pending', -- pending / approved / rejected
    reviewed_by NVARCHAR(50) NULL,                -- 审核人用户名
    review_time DATETIME2 NULL,                   -- 审核时间
    created_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME()
);
```

**表 3 — `operation_logs`（操作日志表）**

```sql
CREATE TABLE operation_logs (
    id INT IDENTITY(1,1) PRIMARY KEY,
    username NVARCHAR(50) NOT NULL,               -- 操作用户
    action NVARCHAR(50) NOT NULL,                  -- 操作类型（LOGIN / START_SIM / STOP_SIM / REVIEW 等）
    target NVARCHAR(200) NULL,                     -- 操作目标
    details NVARCHAR(500) NULL,                    -- 操作详情
    ip_address NVARCHAR(50) NULL,                  -- 客户端 IP
    created_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME()
);
```

**表 4 — `simulation_runs`（仿真运行记录表）**

```sql
CREATE TABLE simulation_runs (
    id INT IDENTITY(1,1) PRIMARY KEY,
    started_by NVARCHAR(50) NOT NULL,              -- 启动操作员
    started_at DATETIME2 NOT NULL,                 -- 开始时间
    ended_at DATETIME2 NOT NULL,                   -- 结束时间
    map_width INT NOT NULL,                        -- 地图宽度
    map_height INT NOT NULL,                       -- 地图高度
    car_count INT NOT NULL,                        -- 小车数量
    algorithm NVARCHAR(20) NULL,                   -- 路径算法（BFS / DFS / ASTAR）
    obstacle_ratio NVARCHAR(20) NULL,              -- 障碍物比例
    tick_interval NVARCHAR(20) NULL,               -- 节拍间隔（ms）
    max_tick INT NOT NULL DEFAULT 0,               -- 最大节拍数
    exploration_rate INT NOT NULL DEFAULT 0,       -- 最终探索率（百分比）
    status NVARCHAR(20) NOT NULL,                  -- completed / aborted / error
    map_block_b64 NVARCHAR(MAX) NULL,              -- 障碍物地图 Base64
    map_sealed_b64 NVARCHAR(MAX) NULL,             -- 封禁区域 Base64
    map_view_final_b64 NVARCHAR(MAX) NULL,         -- 最终视野图 Base64
    car_histories NVARCHAR(MAX) NOT NULL,          -- 小车路径历史 JSON
    exploration_events NVARCHAR(MAX) NOT NULL      -- 探索事件 JSON
);
```

**表 5 — `simulation_run_stats`（仿真统计表，外键关联 simulation_runs）**

```sql
CREATE TABLE simulation_run_stats (
    run_id INT NOT NULL PRIMARY KEY,               -- 关联 simulation_runs.id
    saved_by NVARCHAR(50) NOT NULL,                -- 保存操作员
    saved_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    client_timestamp BIGINT NOT NULL DEFAULT 0,    -- 客户端时间戳
    exploration_rate INT NOT NULL DEFAULT 0,       -- 探索率
    tick INT NOT NULL DEFAULT 0,                   -- 节拍数
    duration INT NOT NULL DEFAULT 0,               -- 持续时间（秒）
    total_steps INT NOT NULL DEFAULT 0,            -- 总步数
    total_effective_steps INT NOT NULL DEFAULT 0,  -- 有效步数
    efficiency_percent INT NOT NULL DEFAULT 0,     -- 效率百分比
    car_count INT NOT NULL DEFAULT 0,              -- 小车数量
    algorithm NVARCHAR(20) NULL,                   -- 算法
    obstacle_ratio FLOAT NOT NULL DEFAULT 0,       -- 障碍物比例
    map_width INT NOT NULL DEFAULT 0,              -- 地图宽
    map_height INT NOT NULL DEFAULT 0,             -- 地图高
    balance_score FLOAT NOT NULL DEFAULT 0,        -- 负载均衡评分
    payload NVARCHAR(MAX) NOT NULL,                -- 完整统计数据 JSON
    CONSTRAINT FK_simulation_run_stats_run
        FOREIGN KEY (run_id) REFERENCES simulation_runs(id)
);
```

> **注意**：启动时还会自动删除旧版 `simulation_stats` 表（如果存在），确保表结构为最新版本。

#### 0.3.3 预设账号

系统首次启动时，`UserStore.initPresetUsers()` 自动在 Redis `auth:users` Hash 中创建三个预设账号（幂等，已存在则跳过）。密码使用 BCrypt 哈希存储。

| 用户名 | 密码 | 角色 | 显示名称 | 说明 |
|--------|------|------|----------|------|
| `admin` | `admin123` | `admin`（管理员） | 管理员 | 最高权限：审核注册、管理用户、查看全部操作日志 |
| `simulator1` | `sim123` | `simulator`（仿真员） | 仿真员1 | 可注册新账号，操作仿真 |
| `analyst1` | `ana123` | `analyst`（统计分析员） | 统计分析员1 | 查看仿真历史记录和统计分析 |

**预设管理员同步写入 SQL Server**：`DatabaseManager.insertPresetAdmin()` 在 SQL Server `users` 表中插入 `admin` 账号（BCrypt 哈希密码），用于登录认证和操作日志记录。

> **安全提醒**：
> - 首次部署后**立即修改 `admin` 密码**。管理员拥有注册审核和用户管理的最高权限。
> - 登录失败超过 5 次，该账号会被锁定 15 分钟（900 秒），锁定时长定义于 `UserStore.LOGIN_LOCK_SECONDS`。
> - `admin` 角色只能通过预设创建，用户自行注册仅可选 `simulator` 或 `analyst` 角色。

### 0.4 Docker 部署

> **Docker 仅在 Person A（基础设施主机）上需要安装和运行。** Person B、C、D 不需要 Docker——他们的模块通过配置 Person A 的 IP 远程使用 Redis 和 RabbitMQ。

基础设施（Redis + RabbitMQ）通过项目根目录的 `docker-compose.yml` 定义和启动。

#### 0.4.1 docker-compose.yml 完整内容

```yaml
services:
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    restart: unless-stopped

  rabbitmq:
    image: rabbitmq:3.12-management-alpine
    ports:
      - "5672:5672"       # AMQP 协议端口（模块间消息通信）
      - "15672:15672"     # Web 管理控制台端口
    environment:
      RABBITMQ_DEFAULT_USER: guest
      RABBITMQ_DEFAULT_PASS: guest
    restart: unless-stopped
```

#### 0.4.2 启动基础设施

```powershell
# 在项目根目录执行
cd substation-patrol
docker compose up -d
```

#### 0.4.3 验证容器运行状态

```powershell
docker ps
```

预期输出：两个容器（`substation-patrol-redis-1` 和 `substation-patrol-rabbitmq-1` 或类似名称），状态均为 `Up`。

#### 0.4.4 验证端口可达

```powershell
# 测试 Redis 端口
Test-NetConnection localhost -Port 6379
# 预期：TcpTestSucceeded : True

# 测试 RabbitMQ AMQP 端口
Test-NetConnection localhost -Port 5672
# 预期：TcpTestSucceeded : True
```

#### 0.4.5 RabbitMQ 管理控制台

浏览器访问 **http://localhost:15672**，使用 `guest` / `guest` 登录。

在 **Queues** 标签页可以查看各模块的消息队列和消费者数量（参见 §2.6）。

#### 0.4.6 停止容器

```powershell
docker compose down           # 停止并移除容器（保留 Docker 数据卷）
docker compose down -v        # 停止并移除容器 + 删除数据卷（清除所有 Redis 和 RabbitMQ 数据）
```

> **提示**：`docker compose down -v` 会清除 Redis 中的所有数据（包括会话、仿真状态、预设账号等），下次启动时系统会自动重建预设账号。如果仅需重启容器而不清数据，使用 `docker compose restart`。

### 0.6 防火墙配置

分布式部署时，基础设施所在机器（Person A）和 Display 所在机器（Person D）需要放行对应端口，其他机器才能访问。

#### 0.6.1 Windows 防火墙（管理员 PowerShell）

**Person A — 基础设施主机（Redis + RabbitMQ）：**

```powershell
# 以管理员身份打开 PowerShell，逐一执行
New-NetFirewallRule -DisplayName "Redis6379" -Direction Inbound -Protocol TCP -LocalPort 6379 -Action Allow
New-NetFirewallRule -DisplayName "RabbitMQ5672" -Direction Inbound -Protocol TCP -LocalPort 5672 -Action Allow
New-NetFirewallRule -DisplayName "RabbitMQ15672" -Direction Inbound -Protocol TCP -LocalPort 15672 -Action Allow
```

**Person D — Display 主机（HTTP + WebSocket）：**

```powershell
New-NetFirewallRule -DisplayName "Display8887" -Direction Inbound -Protocol TCP -LocalPort 8887 -Action Allow
New-NetFirewallRule -DisplayName "DisplayWS8888" -Direction Inbound -Protocol TCP -LocalPort 8888 -Action Allow
```

**SQL Server 主机 — 如果 SQL Server 安装在独立机器上：**

```powershell
New-NetFirewallRule -DisplayName "SQLServer1433" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
```

> **验证规则已生效**：
> ```powershell
> Get-NetFirewallRule -DisplayName "Redis*" | Select DisplayName, Enabled
> ```

#### 0.6.2 Linux 防火墙（UFW）

如果 Docker 或模块运行在 Linux 上：

```bash
# Person A
sudo ufw allow 6379/tcp
sudo ufw allow 5672/tcp
sudo ufw allow 15672/tcp

# Person D
sudo ufw allow 8887/tcp
sudo ufw allow 8888/tcp

# 启用防火墙（如果尚未启用）
sudo ufw enable
sudo ufw status verbose
```

#### 0.6.3 端口清单总览

| 端口 | 协议 | 服务 | 来源 | 放行主机 | 说明 |
|------|------|------|------|----------|------|
| **6379** | TCP | Redis | 全部模块 | Person A | 实时数据通信黑板，所有模块必须可达 |
| **5672** | TCP | RabbitMQ AMQP | 全部模块 | Person A | 消息队列，模块间异步命令传递 |
| **15672** | TCP | RabbitMQ 管理台 | 浏览器 | Person A | Web 管理界面，排查用（可选放行） |
| **8887** | TCP | Display HTTP | 浏览器 | Person D | 仿真页面登录、操作、地图渲染 |
| **8888** | TCP | Display WebSocket | 浏览器 | Person D | 实时推送仿真状态、小车位置、地图更新 |
| **1433** | TCP | SQL Server | Display 模块 | SQL Server 主机 | 数据库连接（通常与 Display 同机，不需要远程放行） |

#### 0.6.4 网络互通验证

分布式联调前，B/C/D 三台机器需验证能否连通 Person A 的端口：

```powershell
# 假设 Person A 的 IP 为 192.168.1.101
ping 192.168.1.101
Test-NetConnection 192.168.1.101 -Port 6379
Test-NetConnection 192.168.1.101 -Port 5672
```

三项均需成功（`TcpTestSucceeded : True`）。若 ping 不通，检查是否连接了访客 WiFi、开启了 AP 隔离（客户端隔离），或 Windows 防火墙未放行。

#### `start_all.bat` 做了什么

## 3. 分布式联调启动

> **适用场景**：四人四台电脑分工启动不同模块，通过 **同一 WiFi / 局域网** 连接同一套 Redis + RabbitMQ。

### 3.1 角色分工速查

| 人员 | 角色标识 | 本机启动内容 | 备注 |
|------|----------|-------------|------|
| **Person A** | `infra` | Docker（Redis + RabbitMQ）+ **Controller（必须最后）** | 基础设施唯一提供者 |
| **Person B** | `car` | Car001、Car002、Car003（按 `cars` 数组） | 每辆车一个进程 |
| **Person C** | `planner` | TaskConfigurator + Navigator + TargetPlanner + StrategySupervisor | 四个规划模块 |
| **Person D** | `display` | SQL Server + Display + 浏览器操作 | 唯一操作员，所有人通过 D 的浏览器访问仿真页面 |

### 3.2 各角色机器需要安装什么

> **核心原则：中间件（Redis、RabbitMQ、SQL Server）只在指定角色的机器上运行，其他角色通过网络远程连接，无需安装对应软件。**

| 需要安装的软件 | Person A | Person B | Person C | Person D | 说明 |
|---------------|:--------:|:--------:|:--------:|:--------:|------|
| **JDK 17+** | ✅ | ✅ | ✅ | ✅ | 四人相同，编译和运行所有 Java 模块 |
| **Maven Wrapper** | ✅ | ✅ | ✅ | ✅ | 项目源码自带，`mvnw.cmd install` |
| **Docker Desktop** | ✅ | ❌ | ❌ | ❌ | Redis + RabbitMQ 容器仅 Person A 运行 |
| **Redis** | ✅ (Docker) | ❌ | ❌ | ❌ | B/C/D 的模块通过 `infra.local.json` 配置 Person A 的 IP 远程连接 |
| **RabbitMQ** | ✅ (Docker) | ❌ | ❌ | ❌ | 同上，远程连接 |
| **SQL Server** | ❌ | ❌ | ❌ | ✅ | **只有 Display 模块访问数据库**，Car/Navigator/Controller 等模块完全不碰 SQL Server |
| **浏览器** | ❌ | ❌ | ❌ | ✅ | 所有人用浏览器打开 `http://<D的IP>:8887`，D 自己用 `localhost:8887` |

> **要点**：
> - **Person B 和 Person C 只需要 JDK + 项目源码**，不需要装 Docker、Redis、RabbitMQ、SQL Server。他们的模块通过配置 Person A 的 IP 远程使用 Redis/RabbitMQ。
> - **Person A 和 Person D 承担所有中间件**：A 负责 Redis + RabbitMQ（Docker），D 负责 SQL Server + Web 页面服务（Java 进程）。
> - **Display 是唯一的 HTTP + WebSocket 服务端**，跑在 Person D 的机器上（端口 8887）。所有人（A/B/C/D）的浏览器都打开 `http://<D的IP>:8887`。前端 HTML/JS/CSS/Unity WebGL 所有文件编译在 Display JAR 内部，由 Person D 启动后对外提供。

### 3.3 各模块与中间件的通信关系

```
                        Redis :6379          RabbitMQ :5672        SQL Server :1433
                       (Person A)             (Person A)             (Person D)

 Person A: Controller     读写 ✅                收发 ✅                  ❌
 Person A: Docker         本机运行 ✅            本机运行 ✅               ❌

 Person B: Car            读写 ✅                收发 ✅                  ❌

 Person C: Navigator      读写 ✅                收发 ✅                  ❌
 Person C: TargetPlanner  只读 ✅                收发 ✅                  ❌
 Person C: TaskConfigurator读写 ✅                收发 ✅                  ❌
 Person C: StrategySuper. 读写 ✅                收发 ✅                  ❌

 Person D: Display        只读 ✅                收发 ✅              读写 ✅  ← 全系统唯一
```

> - **仅有 Display 模块访问 SQL Server**，所有其他模块（Controller、Car、Navigator、TargetPlanner、TaskConfigurator、StrategySupervisor）与数据库零交互。
> - Display 模块在 `DisplayMain.start()` 中初始化 `DatabaseManager`，建立了唯一的数据库连接池。前端页面的登录、注册、统计分析、历史回放等功能，均通过 Display 的 HTTP API 转发到数据库。

### 3.4 硬约束（全组遵守）

| 规则 | 原因 |
|------|------|
| 全组只有 **一套** Redis + RabbitMQ（在 Person A 的 Docker 里） | 多套基础设施会导致状态分裂 |
| 全组只有 **一个** Controller | Controller 有 Redis 单实例锁，重复启动会退出 |
| 全组只有 **一个** Display | 统一入口，避免命令分裂 |
| 全组只有 **一个** TaskConfigurator 消费队列 | 两个消费者会抢消息 |
| 每种规划模块（Navigator/TargetPlanner/StrategySupervisor）通常 **1 个** 消费者 | 多开会抢消息导致卡顿 |
| 同一 carId（如 `Car001`）**不可**在两台电脑各起一个进程 | 状态冲突 |
| **全组仅由 Person D 点一次「开始」** | 其他人只观看，不要重复下发配置 |

### 3.3 编译前置步骤（四人相同）

每台电脑至少执行一次：

```powershell

git pull
.\mvnw.cmd install -DskipTests
```

| **同一 WiFi / 局域网** | `192.168.x.x` 或 `10.x.x.x` | 四人同一教室、实验室，连同一个路由器 |

## 4. 配置说明

### 4.1 `deploy/infra.local.json` 字段

各模块启动时通过 `InfraConnectionConfig.resolve(args)` 自动读取此文件。文件已加入 `.gitignore`，不提交 Git，每人本地维护一份。

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `redisHost` | string | `"localhost"` | Redis 地址；单机为 localhost，分布式 B/C/D 填 Person A 的 IP |
| `redisPort` | int | `6379` | Redis 端口，一般不改 |
| `mqHost` | string | `"localhost"` | RabbitMQ 地址；同上 |
| `mqPort` | int | `5672` | RabbitMQ AMQP 端口 |
| `role` | string | `"infra"` | 角色标识：`infra` / `planner` / `car` / `display`，脚本用 |
| `displayHost` | string | `"localhost"` | Display 所在机器 IP（供生成浏览器 URL） |
| `displayHttpPort` | int | `8887` | Display HTTP 端口 |
| `displayWsPort` | int | `8888` | Display WebSocket 端口 |
| **`dbHost`** | string | `"localhost"` | **SQL Server 地址**（仅 Person D 需要） |
| **`dbPort`** | int | `1433` | **SQL Server 端口**（仅 Person D 需要） |

> Person A/B/C 无需填写数据库字段（也无需安装 SQL Server）。这些字段仅在 Display 模块（Person D）启动时被读取，用于构造 JDBC 连接。详情参见 §3.2（各角色机器需要安装什么）和 §3.3（各模块与中间件的通信关系）。

## 6. 常见问题排查

### 6.1 问题速查表

| 现象 | 可能原因 | 解决办法 |
|------|----------|----------|
| 点「开始」没反应 | TaskConfigurator 未启动或队列无消费者 | 检查 TaskConfigurator 窗口；RabbitMQ 管理台 `http://localhost:15672` 查看 `TaskConfigCmd` 队列 Consumers |
| TaskConfigurator 启动报错 EOF | RabbitMQ 未就绪 | 先 `docker compose up -d`，等 15 秒再启动模块 |
| 车不动 / 探索率 0% | Controller 未启动或启动时机不对 | 确认 Controller 在最后启动，日志出现「等待任务配置」；分布式确认 B/C/D 就绪后 A 再起 Controller |
| 部分车不动 | Person B 未启动对应 Car 进程 | 检查 Car004/005 等是否在 B 机启动 |
| Controller 启动后秒退 | 已有另一个 Controller 在运行（Redis 单实例锁） | 全组仅保留一个 Controller |
| 画面卡顿 | 地图过大 + 节拍太快 + 每拍传整图 | 改用 30×30 地图、节拍 500ms；勿多开模块 |
| `ClassNotFoundException: *Main` | `exec:java` 未加 `-pl` 参数或执行在根项目上 | 确保命令含 `-pl <模块名>`；日志应显示 `@ <模块名>` 而非 `@ car-homework` |
| 登录失败 | SQL Server 未在 Person D 运行 | Person D 启动 SQL Server 服务 |
| 页面能开但地图空白 | WebSocket 未连接 | 检查 8888 端口防火墙；浏览器 F12 → Network → WS 筛选 |
| 仿真后返回 dashboard 跳登录 | 误用 `flushDB` 清掉会话 | 确认使用最新代码，`clearSimulationState()` 保留 `auth:*` |
| 远程连不上 Redis | Person A 防火墙未放行或 Docker 未起 | A 检查 `docker ps` 和防火墙规则；B/C/D 检查 `infra.local.json` 中 IP |
| 远程 Redis 超时（`Read timed out`） | 局域网 延迟大 | 已内置 30s 超时；检查 局域网 连接状态 |
| 连不上 `IP_A:6379` / `5672` | 配置文件 IP 错误或网络不通 | 检查 `infra.local.json`；`ping IP_A`；`Test-NetConnection IP_A -Port 6379` |

### 6.2 自助排查三板斧

1. **RabbitMQ 管理台** — 访问 `http://localhost:15672`（或 `http://IP_A:15672`）→ Queues 标签，检查各队列 **Consumers 是否恰好为 1**
2. **Redis 黑板** — 点「开始」后检查是否存在 `Car001:Position`、`TaskConfig` 等键
3. **模块窗口日志** — 检查是否有 `BUILD FAILURE` 或红色异常栈

### 6.3 Display 启动失败特殊处理

若出现 `ClassNotFoundException: DisplayMain`，说明 Maven 在根项目（`@ car-homework`）而非 display 子模块上执行了 `exec:java`。处理方式：

1. 确认 `scripts/_common.ps1` 已修复（`git pull` 获取最新）
2. 或使用手动两步命令（见附录 §7.3）

## 7. 附录：手动 cmd 命令（脚本失败时备用）

> 当 PowerShell 脚本报 `ClassNotFoundException`、`exec:java` 在根项目执行、或脚本环境不可用时使用以下 cmd 命令。**必须在 cmd 中执行**，不要在 PowerShell 中。

### 7.1 核心规则（两步启动法）

每个模块启动分两步：**先编译，再运行**。两步均在 cmd 中执行：

```cmd
.\mvnw.cmd -pl <模块名> -am compile -q
.\mvnw.cmd -pl <模块名> exec:java -Dexec.mainClass=<Main类全名> [ -Dexec.args="..." ]
```

**成功标志：** 日志出现 `--- exec:java @ <模块名> ---`，例如 `@ display`、`@ car`。
**失败标志：** 出现 `@ car-homework` 且 `ClassNotFoundException` → 说明未加 `-pl` 或两步写反了。

### 7.2 前置准备（任意角色，做一次即可）

```cmd
cd /d substation-patrol
.\mvnw.cmd install -DskipTests
```

确认 `deploy\infra.local.json` 已按角色配置（参见 §4）。

### 7.5 分布式手动 cmd（使用 REMOTE 环境变量）

若 `infra.local.json` 未配置但需临时指定远程 IP，可在 cmd 中设置环境变量：

```cmd
cd /d substation-patrol
set IP_A=192.168.1.101
set REMOTE=--redis-host %IP_A% --mq-host %IP_A%
```

然后在每条 `exec:java` 命令的 `-Dexec.args` 中追加 `%REMOTE%`。示例：

```cmd
# Person C TaskConfigurator 远程版
.\mvnw.cmd -pl task-configurator exec:java -Dexec.mainClass=com.substation.taskconfigurator.TaskConfiguratorMain -Dexec.args="%REMOTE%"

# Person B Car001 远程版
.\mvnw.cmd -pl car exec:java -Dexec.mainClass=com.substation.car.CarMain -Dexec.args="Car001 %REMOTE%"
```

`REMOTE` 环境变量仅对当前 cmd 窗口有效，关闭窗口后失效。

> **注意：** Person A（Controller + Docker 在本机）不需要 `--redis-host` 参数，A 的 `infra.local.json` 中 `redisHost`/`mqHost` 应为 `localhost`。

### 7.6 手动命令常见问题

| 现象 | 处理 |
|------|------|
| `ClassNotFoundException: *Main` | 未加 `-pl`；按两步法「compile → exec:java」重开 |
| 日志显示 `@ car-homework` | 同上；勿用 `exec:java -pl xxx -am` 单条（旧版命令模式） |
| `install` 未做过 | 先执行 `.\mvnw.cmd install -DskipTests` |
| 编译报 `Failed to delete car-*.jar` | 先停止小车 java 进程，再编译 |
| 中文日志乱码 | `chcp 65001`（项目 `.mvn/jvm.config` 和 `start_all.bat` 已默认设置） |
